The selector that looks forward.

:has() matches an element based on what's inside or after it — a real parent selector, at last. Style a container because of its children, or a heading because of what follows it, with zero JavaScript and no class toggling.

01 / PARENT REACTS TO CHILD — interactive

:has(.child:checked)

Tick the checkbox. The card below it changes purely from CSS — no JS listener toggles a class. :has() re-evaluates live as the checkbox's :checked state changes.

This card's border and background react to the checkbox above. 
.group:has(.chk:checked) .card {
  border-color: #2f4fd6;
  background: #eef1fc;
}
/* no JS: :has() re-evaluates whenever the checkbox's :checked state changes */

02 / RELATIONAL SELECTION

:has(+ sibling)

:has() also looks sideways. Here every h3 immediately followed by a <p> gets a solid accent rule; one followed by anything else gets a dashed one instead — the heading "knows" what comes right after it.

Has a paragraph next

This paragraph immediately follows its heading, so the heading above picks up the solid accent rule.

No paragraph next

This is a <div>, not a <p> — the heading above doesn't match, so it falls back to the dashed rule.
h3:has(+ p)      { border-bottom: 3px solid #2f4fd6; }
h3:not(:has(+ p)) { border-bottom: 3px dashed #c3c5bd; }

03 / FORM VALIDATION

:has(:invalid) / :has(:valid)

Type something in the field. Combining :has() with the native :invalid / :valid / :placeholder-shown pseudo-classes rings the whole field group red or green from the browser's own validation state — no validation library required. 

.field:has(input:invalid:not(:placeholder-shown)) input { border-color: #d9531e; }
.field:has(input:valid:not(:placeholder-shown))   input { border-color: #1d5b2c; }
/* :not(:placeholder-shown) skips the empty, untouched state */
