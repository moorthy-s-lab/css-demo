← All demos · CSS light-dark() · Color Module Level 5

Two colors. One decision.

light-dark() chooses between paired values using an element's active color-scheme. It turns repeated theme overrides into compact, local declarations while keeping the user's preference in charge.

01 / BEFORE LIGHT-DARK()

The media-query pattern

Traditionally, a light palette is declared first and every theme token is reassigned inside @media (prefers-color-scheme: dark). It works, but the theme logic lives in a distant second block and grows with the palette. Both possible states are shown here at once for comparison.

Morning notes

The default declarations supply the light palette.

default
Evening notes

The media query reassigns the same theme tokens.

media query 
:root {
  --surface: var(--light-surface);
  --text:    var(--light-text);
}

@media (prefers-color-scheme: dark) {
  :root {
    --surface: var(--dark-surface);
    --text:    var(--dark-text);
  }
}

.card {
  background: var(--surface);
  color: var(--text);
}

02 / FIRST SWITCH

Put both choices beside the property

Declare support for both schemes, then pass the light value first and the dark value second. The browser resolves each function from the element's used color-scheme; the two forced cards expose both results.

Morning notes

The first argument wins in a light scheme.

light
Evening notes

The second argument wins in a dark scheme.

dark 
:root {
  color-scheme: light dark;
}

.card {
  background: light-dark(var(--light-surface), var(--dark-surface));
  color:      light-dark(var(--light-text), var(--dark-text));
}

03 / FORCE THE SCHEME — interactive

Preference by default, overrides when needed

light dark follows the user's preference. A single keyword forces a scheme on this subtree—useful for previews and components that must retain a specific appearance, but not as a reason to ignore a user's choice.

Aa

System preference

light-dark() reads this element's used scheme.

.preview {
  color-scheme: light dark; /* follow preference */
}
.preview.light { color-scheme: light; }
.preview.dark  { color-scheme: dark; }

04 / THEME TOKENS

Resolve semantic colors once

Pair each semantic token at its definition, then let components consume plain names such as --surface and --on-surface. Theme logic stays centralized without a second selector tree.

Three paired tokens style the whole component.

:root {
  --surface:    light-dark(var(--light-surface), var(--dark-surface));
  --on-surface: light-dark(var(--light-text), var(--dark-text));
  --action:     light-dark(var(--light-action), var(--dark-action));
}

.card {
  background: var(--surface);
  color: var(--on-surface);
}
.card a { color: var(--action); }

05 / SCOPED THEMES

Schemes inherit; components can reset them

Because color-scheme inherits, every descendant normally resolves the same way. A nested component can establish a new scheme, and its existing light-dark() declarations immediately follow that local context.

Light workspace

The outer subtree fixes a light used scheme.

Dark command palette

This nested subtree resets only color-scheme.

.workspace {
  color-scheme: light;
  background: light-dark(var(--light-surface), var(--dark-surface));
}

.command-palette {
  color-scheme: dark;
  /* the same light-dark() tokens now resolve to dark */
}

06 / FALLBACKS

Put the older declaration first

Unsupported functional colors invalidate only their declaration. Place a safe light value first, then override it with light-dark(); older browsers keep the first declaration while modern browsers use the second.

Progressively themed

Modern browsers show the forced dark result.

fallback first 
.card {
  /* safe fallback */
  background: var(--light-surface);
  color: var(--light-text);

  /* supporting browsers override it */
  background: light-dark(var(--light-surface), var(--dark-surface));
  color: light-dark(var(--light-text), var(--dark-text));
}
