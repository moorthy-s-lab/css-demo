01 / SPANNING ITEMS

T-junctions around a span

The spec's signature case. When an item spans tracks, a column rule can't run through it — it stops at the item's edge, where the continuing row rule forms a T. Toggle rule-break to watch the segments reroute around the two wide cells.

.grid {
  grid-template-columns: repeat(3, 1fr);
  column-rule: 3px solid #2f4fd6;
  row-rule:    3px solid #d9531e;
  rule-break:  intersection;
}
.grid .wide { grid-column: span 2; }  /* column rule stops here → T */

02 / PAINT ORDER

rule-overlap

Where a thick column rule crosses a thick row rule, one has to sit on top. rule-overlap picks the winner — row-over-column or column-over-row. Toggle it and watch the crossings flip.

This browser doesn't recognise rule-overlap yet — the toggle has no visible effect here. 

column-rule: 14px solid #2f4fd6;
row-rule:    14px solid #d9531e;
rule-overlap: row-over-column;  /* | column-over-row */

04 / INSETS — interactive

cap vs junction insets

Part I's rule-inset trimmed every end equally. The longhands split it: rule-inset-cap pulls rules in only at the container's outer edges, while rule-inset-junction trims them only where they meet a crossing rule. Flip overlap-join to weld the corners back together.

This browser doesn't recognise the rule-inset-cap / rule-inset-junction longhands — the sliders won't move the rules here. 

column-rule: 3px solid #2f4fd6;
row-rule:    3px solid #2f4fd6;
rule-inset-cap:      8px;            /* trim at the outer edges  */
rule-inset-junction: overlap-join;   /* …or weld the crossings   */

05 / MULTICOL

back home, with new powers

column-rule was born in multi-column layout — and the new model folds it in. The classic single rule still works, but now it accepts the per-gap list too: here the two gaps between three text columns carry different colours.

Gap decorations move the job of drawing separators from the children to the container. No per-item borders, no pseudo-elements, no counting.

In multicol the rule lives between text columns. Defaults differ from grid: column-rule-break is intersection, while row-rule-break is none, since the column gaps are what matter here.

Because the value is a list, every column gap can be styled independently — the same syntax you use across grid tracks.

Open this in Chrome or Edge 149+ and the two rules between these columns are real paint, redrawn as the text reflows.

.article {
  columns: 3;
  column-gap: 30px;
  column-rule-width: 2px;
  column-rule-color: #2f4fd6, #d9531e;  /* gap 1, gap 2 */
}

rule-visibility-items

Not every gap wants a rule. rule-visibility-items controls whether rules are drawn between items, around them (including the outer edges), all, or the normal default. The dashed cells below are placeholders to read the edges against.

09 / ANIMATION

rules that move

Rules are paint — and paint can animate. Register the width and colour as typed custom properties with @property, feed them into the rule shorthand, and they interpolate. Hover the grid to thicken and ink the lines; honours prefers-reduced-motion.

↑ hover to animate · or drive the same vars from animation-timeline: scroll()

@property --rule-w { syntax: "<length>"; inherits: true; initial-value: 1px; }
.grid {
  column-rule: var(--rule-w) solid var(--rule-c);
  row-rule:    var(--rule-w) solid var(--rule-c);
  transition: --rule-w .55s ease, --rule-c .55s ease;
}
.grid:hover { --rule-w: 6px; --rule-c: #2f4fd6; }

10 / FALLBACK

the @supports you ship

Until this is Baseline, ship progressive enhancement. Guard the rules behind @supports (row-rule: …), and give non-supporting browsers a border ring instead. Left is the real thing; right is the fallback, drawn with box-shadow so you can see both at once.

row-rule / column-rule

border fallback

.grid { display: grid; gap: 16px; }

/* progressive enhancement */
@supports (row-rule: 1px solid black) {
  .grid { column-rule: 2px solid #2f4fd6; row-rule: 2px solid #2f4fd6; }
}
@supports not (row-rule: 1px solid black) {
  .grid > * { box-shadow: inset 0 0 0 1px #c3c5bd; }
}
